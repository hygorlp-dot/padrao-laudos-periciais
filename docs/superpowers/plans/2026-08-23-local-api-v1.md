# LOCAL_API_V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the seven stabilized Application use cases through a deterministic, loopback-only HTTP API without adding domain logic, direct SQL access, frontend behavior, or external egress.

**Architecture:** Add a `scripts.backend_contract.local_api` package with three boundaries: a pure transport/router that depends only on Application, a standard-library HTTP server that enforces loopback and browser-origin defenses, and one composition root that alone knows SQLite Infrastructure. The transport accepts JSON DTOs, delegates exactly once to the matching Application Service, and serializes canonical models without information loss.

**Tech Stack:** Python 3 standard library only (`http.server`, `json`, `secrets`, `threading`, `urllib.parse`, `datetime`, `uuid`), SQLite3 through the existing adapter, pytest/Hypothesis.

## Global Constraints

- Issue: #6 `[Local API] LOCAL_API_V1`.
- Authoritative base: `5c47a3f627550df1b0dcc8fd49f21834004b930f`.
- Routes: the seven `/v1/workspaces` and artifact-revision operations authorized by the Issue; no update/delete/bulk/admin/health surface.
- Route identity: structural tokens, workspace UUIDs, and revision numbers use their exact raw canonical spelling. Only the dynamic `artifact_kind` and `artifact_id` segments are percent-decoded as strict UTF-8; controls are rejected both before and after decoding. Revisions are ASCII decimal without leading-zero aliases in the range `1..2^53-1`.
- Local threat model: bind only literal `127.0.0.1`; reject public/wildcard hosts, DNS-rebinding Host headers, every browser `Origin`, and every mutation without the exact ephemeral local token.
- Dependency decision: no new runtime dependency. `ThreadingHTTPServer` is sufficient for a bounded local transport and avoids supply-chain/framework expansion.
- DTO strategy: exact top-level request fields; payload remains arbitrary valid JSON and is copied by the existing Application service. Responses are deterministic UTF-8 JSON with canonical Application fields and list order preserved.
- JSON numeric policy V1: integer tokens are accepted only in the interoperable range `[-(2^53-1), 2^53-1]`; integer `-0` is rejected because decoding would erase its sign. Float tokens are accepted only when Python's emitted JSON number preserves the exact decimal value. Unsafe integers in Application output fail closed as `LOCAL_API_SERIALIZATION_FAILURE` rather than reaching a future JavaScript client with silent rounding.
- Error mapping: transport validation `400`; local-security denial `403`; route `404`; wrong method `405`; Application not-found `404`; conflict `409`; integrity/schema `500`; operational repository failure `503`. Error bodies expose stable codes only, never SQL, paths, tokens, payloads, or tracebacks.
- STOP after normal merge and green post-main verification. Do not start frontend, product workflow, AI Gateway, provider, release, installer, telemetry, or cloud work.
