## Platform

web

## Stack

Delegated by the brief: React, TypeScript and Vite with local React state,
plain CSS and browser-native navigation. No desktop host, state-management
framework, UI kit or remote asset service is part of this milestone.

## Users

The primary user is a technical expert preparing and reviewing forensic
engineering work on a desktop. They need a calm, predictable workspace that
keeps the sequence of work visible without exposing implementation details.

## Product Purpose

ARCD turns a stable forensic Core, Application Layer, local persistence and
Local API into usable professional software. Success means the expert can move
through a clear technical workflow while domain authority remains below the UI.

## Positioning

The interface follows the real progression of forensic work rather than
organizing the product around technical modules, generic dashboards or AI
features.

## Operating Context

The durable workflow is Processo, Analise, Planejamento, Vistoria, Evidencias,
Constatacoes, Analise Tecnica, Laudo, Revisao and Exportar. Work occurs locally
on desktop, often for long sessions, with precision, traceability and quiet
focus valued over novelty.

## Capabilities and Constraints

- This milestone provides only the application shell, navigation, routing and
  presentation states.
- It does not start a navigable forensic case or execute domain use cases.
- Core, Application, SQLite and Local API contracts remain frozen and are not
  imported or reimplemented in the frontend.
- The frontend has no Local API token, secrets, automatic network calls,
  analytics, telemetry, remote fonts or remote assets.
- Real case material and private references never enter the frontend source.

## Brand Commitments

The product name is ARCD. The interface voice is concise, professional,
technical and action-oriented. It must feel precise and contemporary without
resembling a generic SaaS dashboard, CRM, AI product or marketing page.

## Evidence on Hand

No real case content, customer claims, metrics, photographs or brand assets are
available for this shell. The UI must not fabricate them. Product placeholders
describe only workflow readiness and clearly state when no case is selected.

## Product Principles

- User workflow first.
- Simple by default; technical detail only on demand.
- One primary action per view.
- Domain logic stays below the UI.
- Assurance remains proportional to risk.

## Accessibility & Inclusion

The shell uses semantic landmarks, real links, visible focus, keyboard
navigation, `aria-current`, sufficient contrast and reduced-motion support.
